三端增强版 MVP 边界

先确认首发版本的深度，而不是功能名称是否“存在”

摊主端
必须首发
  • 市集发现 / 搜索 / 筛选
  • 详情页与费用透明展示
  • 报名申请与资质上传
  • 报名进度 / 消息通知
  • 在线支付报名费 / 摊位费
增强但可降级
  • 基础经营看板
  • 收藏 / 档期管理
  • 评价与信用档案
不进 MVP
  • 完整 POS 收银
  • 高级库存与客流探针
  • 私域社群工具

摊主端重点

核心目标是让摊主完成发现、报名、支付、确认，不把经营工具做成主线阻塞项。

主办方端
必须首发
  • 市集创建与发布
  • 报名审核与资质复核
  • 摊位地图基础配置
  • 人工 + 规则式分配
  • 订单 / 退款 / 结算台账
增强但可降级
  • 活动数据看板
  • 宣传素材协同
  • 现场签到与通知
不进 MVP
  • 3D 场地图
  • 复杂 AI 分配算法
  • 政府系统对接

主办方端重点

先把发布、审核、分配、收款和履约流程跑通，智能化先做规则引擎而不是 AI 黑盒。

消费者端
必须首发
  • 周边市集发现
  • 市集详情 / 摊主预览
  • 收藏 / 开场提醒
  • 活动日历
增强但可降级
  • 预约到访
  • 评论 / 打卡 / 投票
  • 专题推荐页
不进 MVP
  • 线上商城闭环
  • 即时配送
  • 复杂会员体系

消费者端重点

首版承担引流和种草，不承担重交易；避免把消费者端做成另一套电商系统。

请重点判断

A

边界合理

按这套 MVP 深度继续往下设计。

B

消费者端还要更重

需要把互动或交易再前置一些。

C

摊主经营工具更重

需要把记账、库存、分析提到 MVP 主路径。
