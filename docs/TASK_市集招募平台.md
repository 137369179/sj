# TASK: 市集招募平台

## 1. 文档信息

- 项目名称：市集招募平台
- 文档阶段：Atomize
- 文档日期：2026-05-01
- 目标：将设计方案拆解为可独立验证、可自动执行、可审批的原子任务集合

## 2. 拆解原则

- 每个任务必须有明确输入与输出
- 每个任务必须有独立验收标准
- 每个任务必须尽量控制在单一职责边界内
- 高风险任务必须显式挂接审批门
- 任务依赖必须形成有向无环图
- 优先拆解 MVP 闭环任务，再定义终局扩展任务

## 5. MVP 原子任务清单

以下任务为优先级最高、最适合自动化执行的第一批任务。

## 5.1 T1-1 初始化单仓结构与工程规范

- 目标：创建统一前后端单仓结构
- 输入：技术选型、目录规范、编码规范
- 输出：可运行工程、基础依赖、统一 lint/test/build 配置
- 依赖：无
- 约束：使用 TypeScript；配置环境变量模板；禁止硬编码密钥
- 验收标准：
  - 本地可启动
  - lint/test/build 命令可执行
  - 基础目录结构符合设计文档
- 自动化级别：全自动可执行

## 5.2 T1-2 建立认证与权限框架

- 目标：支持摊主、主办方、平台管理员三种角色
- 输入：角色模型、登录策略、权限矩阵
- 输出：登录、会话、路由守卫、中间件、角色校验
- 依赖：T1-1
- 约束：审计登录事件；敏感接口必须鉴权
- 验收标准：
  - 三角色可区分登录与访问
  - 未授权访问被正确拦截
  - 权限校验有单元测试
- 自动化级别：半自动，鉴权策略需人工复核

## 5.3 T1-3 建立数据库与迁移体系

- 目标：定义用户、市集、摊位、报名、通知等核心表
- 输入：领域模型与状态机
- 输出：Schema、迁移脚本、种子数据
- 依赖：T1-1
- 约束：所有状态字段枚举化；关键关系加索引；防重复分配约束
- 验收标准：
  - 能完成数据库初始化
  - 能回放迁移
  - 核心表关系符合设计文档
- 自动化级别：半自动，迁移需人工审批

## 5.4 T1-4 建立 UI 设计系统基础

- 目标：统一基础组件、表单、列表、状态标签、弹窗和布局
- 输入：设计原则、角色端页面需求
- 输出：UI 组件库与样式基线
- 依赖：T1-1
- 约束：响应式、语义化、ARIA 基线
- 验收标准：
  - 组件可复用
  - 具备基础无障碍属性
  - 覆盖后台表格和移动表单场景
- 自动化级别：全自动可执行

## 5.5 T2-1 主办方创建/编辑/发布市集

- 目标：支持主办方创建和发布招募信息
- 输入：市集表单定义、发布状态机
- 输出：页面、接口、数据库持久化、状态流转
- 依赖：T1-2, T1-3, T1-4
- 约束：草稿与发布分离；表单校验完整
- 验收标准：
  - 主办方可保存草稿
  - 可发布成功并在摊主端可见
  - 状态流转有集成测试
- 自动化级别：全自动可执行

## 5.6 T2-2 摊主浏览、搜索、筛选市集

- 目标：支持按城市、时间、主题筛选市集
- 输入：市集列表字段与筛选规则
- 输出：列表页、搜索接口、筛选组件、空态页
- 依赖：T2-1
- 约束：首屏性能稳定；支持分页
- 验收标准：
  - 支持关键筛选组合
  - 可访问公开详情页
  - 空结果和加载态可用
- 自动化级别：全自动可执行

## 5.7 T2-3 摊主提交报名申请

- 目标：完成报名表单、资质上传、偏好填报
- 输入：申请字段、附件规则、状态机
- 输出：报名页面、提交接口、附件记录
- 依赖：T1-3, T1-4, T2-2
- 约束：上传失败可重试；提交操作幂等
- 验收标准：
  - 可成功提交申请
  - 附件与申请关联正确
  - 重复提交不会生成脏数据
- 自动化级别：全自动可执行

## 5.8 T2-4 主办方查看申请列表与详情

- 目标：支持按状态、品类、提交时间查看申请
- 输入：申请查询条件与显示字段
- 输出：后台列表页、详情页、查询接口
- 依赖：T2-3
- 约束：支持分页与排序；显示关键附件
- 验收标准：
  - 申请可被检索
  - 列表和详情字段完整
  - 不同状态有明显标识
- 自动化级别：全自动可执行

## 5.9 T2-5 主办方审核申请

- 目标：支持通过、拒绝、备注
- 输入：审核规则、状态约束
- 输出：审核操作接口、审计日志、通知事件
- 依赖：T2-4
- 约束：同一申请防并发重复审核
- 验收标准：
  - 状态机合法流转
  - 审核记录可追踪
  - 审核结果可通知摊主
- 自动化级别：半自动，审核规则需人工校验

## 5.10 T2-6 主办方配置摊位

- 目标：支持创建基础摊位数据
- 输入：摊位属性、状态定义、所属市集
- 输出：摊位管理页面与接口
- 依赖：T2-1, T1-3
- 约束：不做复杂地图，仅支持列表/网格配置
- 验收标准：
  - 能创建、编辑、停用摊位
  - 摊位与市集绑定正确
  - 状态可追踪
- 自动化级别：全自动可执行

## 5.11 T2-7 主办方分配摊位并通知

- 目标：将已通过申请分配到可用摊位
- 输入：通过状态申请、摊位列表
- 输出：分配逻辑、通知事件、分配记录
- 依赖：T2-5, T2-6
- 约束：一摊位同一时间不可重复分配
- 验收标准：
  - 分配成功后状态同步更新
  - 冲突时明确报错
  - 摊主收到结果通知
- 自动化级别：半自动，分配规则需人工确认

## 5.12 T2-8 摊主查看状态与结果

- 目标：让摊主随时查看报名状态
- 输入：申请记录、审核结果、摊位结果
- 输出：个人中心中的报名管理页
- 依赖：T2-5, T2-7
- 约束：状态展示清晰；拒绝原因可见
- 验收标准：
  - 可查看状态流转
  - 可查看结果与备注
  - 通知可回溯
- 自动化级别：全自动可执行

## 5.13 T2-9 平台后台审核主办方与市集内容

- 目标：避免低质量或违规市集直接发布
- 输入：主办方资料、市集信息
- 输出：平台审核页面、审核状态、审计记录
- 依赖：T2-1
- 约束：保留人工审核门；日志不可删改
- 验收标准：
  - 平台可审核主办方和市集
  - 被拒绝对象不可公开展示
  - 审核记录可检索
- 自动化级别：半自动，必须人工审批

## 5.14 T2-10 市场级基础看板

- 目标：展示报名数量、审核通过率、摊位使用率等
- 输入：市集、申请、摊位、通知数据
- 输出：基础统计接口与可视化卡片
- 依赖：T2-1 至 T2-9
- 约束：只做基础聚合，不做预测分析
- 验收标准：
  - 核心指标可见
  - 数据口径固定
  - 看板支持按市集查看
- 自动化级别：全自动可执行

## 7. 自动化执行策略

## 7.1 任务分类

- A 类：可全自动执行
- B 类：自动执行 + 人工复核
- C 类：必须人工审批后执行

### 分类规则

- A 类：UI 组件、列表页、普通表单、非高风险接口、埋点、测试补充
- B 类：鉴权、数据库迁移、状态机、分配逻辑、通知通道
- C 类：支付、生产环境配置、删除性迁移、外部系统对接、风控策略

## 7.2 执行流水线

```mermaid
flowchart LR
  Input["任务输入"] --> Analyze["解析契约"]
  Analyze --> Execute["执行编码"]
  Execute --> Verify["运行测试/校验"]
  Verify --> Review["自动审查/人工复核"]
  Review --> Merge["合并或驳回"]
```

## 7.3 单任务执行模板

每个自动任务必须附带：

- 任务编号
- 目标说明
- 输入契约
- 输出契约
- 依赖任务
- 变更边界
- 验证命令
- 回滚方式
- 风险等级

## 8. 任务依赖规则

- 不允许跨阶段跳依赖
- 先基础设施，再业务闭环，再增强运营，再生态扩展
- 单任务最多依赖 3 个上游任务，避免耦合过高
- 任何任务若依赖未完成，不得进入自动执行队列

## 9. 审批门定义

### 9.1 必须人工审批的场景

- 新增或修改鉴权规则
- 数据库破坏性迁移
- 外部支付与短信网关接入
- 涉及生产资源写入
- 涉及隐私敏感字段处理
- 大规模跨模块重构

### 9.2 可自动放行的场景

- 页面与组件新增
- 列表查询与详情展示
- 常规业务表单
- 基础统计接口
- 文档与测试补充

## 10. 测试策略映射

每类任务最少测试要求如下：

- 页面任务：组件测试 + 关键交互测试
- API 任务：接口测试 + 权限测试
- 状态机任务：单元测试 + 集成测试
- 数据迁移任务：迁移回放测试
- 通知任务：事件触发与失败重试测试

## 11. 任务完成定义

一个任务只有在以下条件全部满足时才算完成：

1. 代码已生成或更新
2. 验证命令通过
3. 文档同步更新
4. 风险项被记录
5. 需要审批的任务已获得批准

## 12. Atomize 验收标准

当以下条件全部满足时，任务拆解阶段通过：

1. MVP 覆盖完整
2. 每个核心任务都可独立验证
3. 依赖关系无循环
4. 自动化门禁清晰
5. 后续 Automate 阶段可以直接按任务编号推进
