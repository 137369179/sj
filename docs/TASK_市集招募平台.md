# TASK: 市集招募平台

## 1. 文档信息

- 项目名称：市集招募平台
- 文档阶段：Atomize
- 文档日期：2026-05-01
- 目标：将设计方案拆解为可独立验证、可自动执行、可审批的原子任务集合

## 2. 拆解原则

- 每个任务必须有明确输入与输出
- 每个任务必须有独立验收标准
- 每个任务必须尽量控制在单一职责边界内
- 高风险任务必须显式挂接审批门
- 任务依赖必须形成有向无环图
- 优先拆解 MVP 闭环任务，再定义终局扩展任务
- 本文采用 `B 中颗粒` 标准，不采用粗颗粒功能包，也不采用超细碎文件级任务

## 2.1 中颗粒任务标准

- 1 个任务只覆盖 1 个可独立验证的功能切片
- 1 个任务最多涉及 `1 个页面或组件组 + 1 组 API + 1 组数据变更`
- 1 个任务应可在 `30-90 分钟` 内由单个 Agent 独立完成
- 1 个任务的验证命令必须可单独执行，不能依赖整站人工联调
- 1 个任务必须具备明确回滚边界，避免把多个高风险改动绑在同一个任务内
- 业务上以 `Epic -> 子任务` 形式组织；执行时只下发子任务，不直接下发 Epic

## 7. 自动化执行策略

## 7.1 任务分类

- A 类：可全自动执行
- B 类：自动执行 + 人工复核
- C 类：必须人工审批后执行

### 分类规则

- A 类：UI 组件、列表页、普通表单、非高风险接口、埋点、测试补充
- B 类：鉴权、数据库迁移、状态机、分配逻辑、通知通道
- C 类：支付、生产环境配置、删除性迁移、外部系统对接、风控策略

## 7.2 执行流水线

```mermaid
flowchart LR
  Input["任务输入"] --> Analyze["解析契约"]
  Analyze --> Execute["执行编码"]
  Execute --> Verify["运行测试/校验"]
  Verify --> Review["自动审查/人工复核"]
  Review --> Merge["合并或驳回"]
```

## 7.3 单任务执行模板

每个自动任务必须附带：

- 任务编号
- 目标说明
- 输入契约
- 输出契约
- 依赖任务
- 变更边界
- 验证命令
- 回滚方式
- 风险等级

## 8. 任务依赖规则

- 不允许跨阶段跳依赖
- 先基础设施，再业务闭环，再增强运营，再生态扩展
- 单任务最多依赖 3 个上游任务，避免耦合过高
- 任何任务若依赖未完成，不得进入自动执行队列

## 9. 审批门定义

### 9.1 必须人工审批的场景

- 新增或修改鉴权规则
- 数据库破坏性迁移
- 外部支付与短信网关接入
- 涉及生产资源写入
- 涉及隐私敏感字段处理
- 大规模跨模块重构

### 9.2 可自动放行的场景

- 页面与组件新增
- 列表查询与详情展示
- 常规业务表单
- 基础统计接口
- 文档与测试补充

## 10. 测试策略映射

每类任务最少测试要求如下：

- 页面任务：组件测试 + 关键交互测试
- API 任务：接口测试 + 权限测试
- 状态机任务：单元测试 + 集成测试
- 数据迁移任务：迁移回放测试
- 通知任务：事件触发与失败重试测试

## 11. 任务完成定义

一个任务只有在以下条件全部满足时才算完成：

1. 代码已生成或更新
2. 验证命令通过
3. 文档同步更新
4. 风险项被记录
5. 需要审批的任务已获得批准

## 12. Atomize 验收标准

当以下条件全部满足时，任务拆解阶段通过：

1. MVP 覆盖完整
2. 每个核心任务都可独立验证
3. 依赖关系无循环
4. 自动化门禁清晰
5. 后续 Automate 阶段可以直接按任务编号推进
