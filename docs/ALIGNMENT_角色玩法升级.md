# ALIGNMENT: 角色玩法升级

## 1. 文档信息

- 项目名称：市集招募平台
- 文档阶段：Align
- 文档日期：2026-05-03
- 功能主题：摊主与主办方双角色玩法升级
- 文档目标：明确双角色在成交闭环中的目标差异、行为规范、页面玩法方向与本轮改造边界

## 2. 背景

当前平台已经具备基础多角色账号、注册登录、报名审核、摊位分配和账号中心能力，但“摊主端”和“主办方端”仍更像在同一套系统里切不同菜单，角色之间的目标差异、工作节奏差异和行为规范差异还不够鲜明。

本轮需要解决的不是“再加几个页面”，而是把双角色从产品逻辑上真正拆开：

- 摊主端要更像“机会获取与报名进度产品”
- 主办方端要更像“招商运营控制台”
- 平台要围绕成交闭环建立更清晰的规则、状态和反馈机制

## 3. 本轮目标

### 3.1 核心目标

- 让摊主更快判断“值不值得报”
- 让主办方更快完成“筛选谁、录取谁、如何招满”
- 让双边围绕同一成交闭环形成不同但互相对齐的行为路径
- 让平台规则显式表达什么是好行为、什么是坏行为

### 3.2 优先级确认

本轮优先目标已确认：

- 优先优化 `成交闭环`
- 主办方主要定位为 `招商运营方`
- 输出内容同时覆盖 `业务规则` 与 `页面玩法`

## 4. 角色定义

### 4.1 摊主

- 角色本质：机会筛选者、报名执行者、履约参与者
- 第一问题：我要不要报
- 核心压力：时间成本、报名成本、通过率不确定、结果不透明
- 核心诉求：低决策成本、低重复劳动、结果透明、履约清晰

### 4.2 主办方

- 角色本质：招商运营者、审核决策者、摊位配置者、成场责任人
- 第一问题：我要录谁
- 核心压力：报名质量参差、审核堆积、摊位错配、确认流失、现场风险
- 核心诉求：高效率招募、高质量筛选、可控分配、稳定成场

## 5. 产品定位结论

### 5.1 摊主端定位

- 机会驱动
- 移动优先
- 决策轻量
- 状态清晰
- 进度导向

一句话定义：

> 帮摊主用最少时间找到合适市集、完成高质量报名，并清楚知道下一步该做什么。

### 5.2 主办方端定位

- 运营驱动
- 桌面优先
- 控制导向
- 风险可见
- 结果导向

一句话定义：

> 帮主办方更快招满、更少错配、更少履约事故地把一场招募运营成结果。

## 6. 本轮范围

### 6.1 纳入范围

- 双角色产品定位重构
- 双角色页面结构和信息层级重构方案
- 双角色状态机与规则设计
- 双角色行为规范与平台激励/约束逻辑
- 页面与逻辑改造的原子任务拆解

### 6.2 不纳入范围

- 消费者端玩法设计
- 平台管理员后台重构
- 支付和结算规则重构
- 完整信用评分系统
- OCR、智能推荐、地图和可视化摊位编排算法
- 新设备提醒、限流、复杂风控策略的完整实现

## 7. 核心问题

本轮设计重点回答以下问题：

1. 为什么摊主端和主办方端不能继续共用同一种产品逻辑
2. 摊主在成交闭环里最关键的决策节点是什么
3. 主办方在成交闭环里最关键的控制节点是什么
4. 哪些规则必须强约束，哪些规则适合柔性引导
5. 平台如何通过状态、提示、排序和留痕来减少双边冲突

## 8. 关键决策

- 决策 1：采用“双边交易型”角色设计，而不是内容社区型或场地方后台型
- 决策 2：摊主端按照“机会池 + 报名进度器”设计
- 决策 3：主办方端按照“招商运营控制台”设计
- 决策 4：优先把规则、状态和反馈表达清楚，再考虑更复杂的智能匹配与商业机制
- 决策 5：平台重点奖励高质量报名、高效率审核和高履约率行为

## 9. 风险与边界

### 9.1 风险

- 角色设计过于抽象，最后只变成文案调整
- 页面差异不够，导致两个角色仍然像同一后台不同菜单
- 规则过硬，伤害摊主报名转化
- 规则过软，主办方审核与履约管理继续失控

### 9.2 控制策略

- 每个角色都必须绑定“目标、行为、页面、规则”四件套
- 优先改造首页、列表、详情、进度和待办，而不是一次铺满所有页面
- 把规则分成强约束和柔性引导两层
- 先做成交闭环可见性，再逐步做更强信用和风控

## 10. 成功标准

- 用户一眼能看出摊主端和主办方端的目标差异
- 摊主端页面优先回答“值不值得报、现在到哪一步、下一步做什么”
- 主办方端页面优先回答“哪里堵塞、哪里有风险、哪批人该先处理”
- 双边状态流转清晰且语义一致
- 角色行为规范、平台奖励和约束逻辑有明确落点
- 后续实现任务可以被拆成可独立交付的前端、服务端和规则层任务

## 11. 验收标准

当以下条件全部满足时，Align 阶段通过：

1. 双角色定位已清晰区分
2. 本轮目标与非目标边界明确
3. 页面玩法与业务规则方向已收敛
4. 强约束规则与柔性规则边界明确
5. 后续 Architect 和 Atomize 阶段已有足够输入

## 12. 结论

本轮角色玩法升级的核心，不是“给不同角色多做几张页面”，而是把同一成交闭环中的不同目标与行为显式产品化：

- 摊主要的是 `少浪费`
- 主办方要的是 `少出错`
- 平台要做的是 `让高质量成交更容易发生`
