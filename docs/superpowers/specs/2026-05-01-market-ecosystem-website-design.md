# 市集三端生态官网雏形设计方案

## 1. 背景

当前仓库仅包含项目简介与一份“三端增强版 MVP 边界”草案页面，尚未具备可对外展示的平台官网。现阶段需要先交付一版可本地演示、信息完整、风格统一的官网雏形，用于说明平台定位、三端价值与核心业务流程，并为后续继续扩展成正式官网或产品前台提供基础。

## 2. 本期目标

- 交付一个多页面官网雏形，而不是后台系统或完整业务应用。
- 用官网形式讲清摊主、主办方、消费者三端生态关系。
- 将现有“MVP 边界”思路升级为更完整的品牌叙事与场景说明。
- 提供明确的页面结构、内容模块与 CTA，支撑演示、评审和下一阶段开发。

## 3. 非目标

- 不实现登录、注册、支付、报名、审核等真实业务流程。
- 不接入后端接口、数据库或 CMS。
- 不制作复杂动画、账户系统、内容管理后台。
- 不在首期处理 SEO、埋点、表单投递、国际化等生产级能力。

## 4. 目标用户

本期官网面向三类受众，但首页以“平台生态说明”视角统一讲述：

- 摊主：关注发现活动、报名入驻、付款确认、经营辅助。
- 主办方：关注发布活动、筛选摊主、摊位配置、订单结算、履约协同。
- 消费者：关注活动发现、内容浏览、收藏提醒、到场转化。

## 5. 核心信息架构

本期交付 4 个页面：

1. 首页
2. 摊主端场景页
3. 主办方端场景页
4. 消费者端场景页

### 5.1 首页

首页承担品牌官网与三端导航入口双重角色，建议包含以下模块：

1. Hero 首屏
   - 平台名称/主标题
   - 三端生态价值副标题
   - 主 CTA 与次 CTA
2. 三端价值总览
   - 摊主端、主办方端、消费者端三张入口卡片
   - 每张卡片包含一句核心收益与跳转按钮
3. 平台如何运转
   - 使用 3 至 5 步流程展示“发现/发布 -> 报名/审核 -> 分配/履约 -> 到场/转化”
4. 核心能力模块
   - 招募与筛选
   - 支付与结算
   - 内容与通知
   - 研究与文案优化
5. 方法论/策略模块
   - 将你提供的“提示词指令集”转译为平台策略能力，例如微文案优化、引导流程设计、用户研究与页面方案生成
6. 可信度模块
   - 场景示例、平台原则、适配对象或模拟案例
7. CTA 结尾区
   - 引导进一步咨询、申请试用或查看场景页

### 5.2 摊主端场景页

重点表达“摊主如何更高效地找到并参与市集”活动：

- 摊主价值主张
- 典型使用流程：发现活动 -> 查看详情 -> 报名申请 -> 资料上传 -> 支付确认 -> 等待通知
- 关键能力：搜索筛选、费用透明、进度通知、档期管理、基础经营辅助
- 常见痛点与改进点
- 对应 CTA

### 5.3 主办方端场景页

重点表达“主办方如何更高效地组织与运营活动”：

- 主办方价值主张
- 典型使用流程：创建活动 -> 招募摊主 -> 资质审核 -> 摊位分配 -> 订单结算 -> 现场协同
- 关键能力：活动发布、审核、摊位配置、规则式分配、台账管理
- 常见痛点与改进点
- 对应 CTA

### 5.4 消费者端场景页

重点表达“消费者如何更轻松地发现并参与市集活动”：

- 消费者价值主张
- 典型使用流程：发现活动 -> 浏览详情 -> 收藏提醒 -> 到场参与
- 关键能力：活动推荐、摊主预览、提醒、轻互动
- 常见痛点与改进点
- 对应 CTA

## 6. 内容策略

### 6.1 语气与风格

- 专业、清晰、产品化。
- 强调“效率、透明、协同、增长”。
- 避免空泛营销话术与过度技术术语。

### 6.2 与现有素材的衔接

现有 `mvp-boundary.html` 已明确三端首期边界。官网内容应吸收其核心判断：

- 摊主端主线是发现、报名、支付、确认。
- 主办方端主线是发布、审核、分配、收款、履约。
- 消费者端主线是引流、种草、提醒与到场转化。

官网中不直接复用原始草案结构，而是将其转化为更适合外部阅读的叙事表达。

### 6.3 “提示词指令集”的官网化表达

你提供的提示词内容不作为单独工具页首期上线，而作为“平台策略与增长能力”模块的内容来源，拆解为以下展示方向：

- 微文案优化：说明平台如何优化错误提示、空状态和操作引导。
- 用户流程设计：说明平台如何优化新手引导、旅程路径与转化节点。
- 用户研究支持：说明平台如何提炼用户原话、访谈问题与决策顾虑。
- 页面方案生成：说明平台如何帮助形成结构化页面方案与内容框架。

## 7. 交互与组件设计

本期使用轻交互方案，保证可演示、易实现、可扩展：

- 顶部导航：支持页面跳转与锚点跳转。
- 价值卡片：点击进入三端场景页。
- 流程步骤区：采用分步卡片或时间线样式。
- 能力模块区：采用网格卡片展示。
- CTA 区：统一按钮样式和状态反馈。
- 响应式布局：至少适配桌面与移动窄屏。

不做的交互：

- 不实现复杂动效编排。
- 不实现多步骤表单。
- 不实现身份切换、登录态、收藏等真实状态管理。

## 8. 技术方案

考虑到当前仓库缺少应用框架，本期优先采用静态多页面实现：

- 首页文件 1 个
- 场景页文件 3 个
- 共享样式文件 1 个
- 共享脚本文件 1 个

建议结构示例：

```text
/workspace
  index.html
  vendor.html
  organizer.html
  consumer.html
  assets/
    styles.css
    app.js
```

技术要求：

- 使用原生 HTML、CSS、JavaScript 完成。
- 尽量复用公共组件样式与交互逻辑。
- 保持文件结构简单，方便后续迁移到框架化项目。

## 9. 页面级验收标准

### 9.1 首页

- 首屏能在 5 秒内让用户理解平台是做什么的。
- 三端入口清晰，用户能继续进入对应场景页。
- 至少包含一段平台运转流程和一段能力说明。
- 明确给出主 CTA 和次 CTA。

### 9.2 场景页

- 每个场景页都包含价值主张、流程、能力、痛点、CTA。
- 每页都能与首页形成统一视觉语言。
- 页面信息层次清楚，不出现大段难读文本堆叠。

### 9.3 体验质量

- 页面在本地可直接预览。
- 导航、按钮、链接行为正常。
- 布局在常见桌面宽度和移动宽度下不破版。

## 10. 风险与后续扩展

### 10.1 当前风险

- 当前缺少品牌名、真实案例、正式品牌视觉，因此首版更偏“高保真官网雏形”而非最终品牌站。
- 若后续需要承接真实线索收集，还需补充联系表单与数据投递链路。

### 10.2 后续扩展方向

- 升级为 React/Next.js 项目。
- 增加表单提交、埋点和 SEO。
- 扩展出“提示词工作台/研究中心”页面。
- 接入真实案例、FAQ、价格方案、试用申请等内容。

## 11. 实施边界结论

本期应优先完成“可讲清三端价值、可本地演示、可继续扩展”的官网雏形。所有真实业务闭环、复杂工具能力和生产级基础设施均延后到下一阶段。
