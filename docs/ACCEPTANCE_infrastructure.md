# 验收摘要：基础设施与运维演进 (P3-4)

## 1. 验证目标

- **真实数据 Seed**：编写自动化数据播种脚本，确保任何新加入的开发者（或在沙盒环境中）都能一键获取丰富的“模拟生产环境”数据结构。
- **Docker 化部署**：提供标准的 `Dockerfile` 和 `docker-compose.yml`，使得系统不仅能在开发环境下运行，更能够被直接部署到生产服务器。

## 2. 功能完整性

### 2.1 Prisma 数据播种 (`prisma/seed.ts`)
- 脚本内囊括了所有角色的创建：
  - 1 名全局 `Admin`
  - 2 名市集主办方 (`Organizer`)
  - 3 名独立摊主 (`Vendor`)
- **真实业务场景串联**：
  - 创建了多个处于不同生命周期的市集（草稿态、已上架态）。
  - 创建了多个处于不同申请状态的 `Application`（待审核、已通过、已分配摊位、**已支付**）。
  - 触发了 `Order` 的生成以及 `Stall` 的分配逻辑关联。
- 使用 `upsert` 操作来保障脚本幂等性，任何时候执行 `pnpm db:seed` 都能获得一个完美运行的“咖啡市集”初始沙盘。

### 2.2 容器化部署架构
- **精简的多阶段构建 Dockerfile**：
  - 阶段 1：`deps` 仅安装依赖（结合 `pnpm` workspace 特性）。
  - 阶段 2：`builder` 构建 Next.js `standalone` 产物。
  - 阶段 3：`runner` 仅运行编译后的代码，极大地缩小了镜像体积，并提升了运行安全性（使用 `nextjs` 无特权用户）。
- **全自动 docker-compose 编排**：
  - 在根目录提供 `docker-compose.yml`。
  - 定义了 `web` 节点（构建自 Dockerfile）与 `db` 节点（Postgres 15）。
  - 配置了挂载卷 (`volumes`) 来持久化数据库文件以及通过 `STORAGE_PROVIDER=local` 时产生的文件上传目录，达到了一键 `docker-compose up -d` 即可拉起全套业务的终极目标。

## 3. 验收总结

基础设施 P3-4 的完善，宣告该项目已**彻底脱离了纯原型 (Prototype) 阶段**，进化为了一个可演示、可部署、数据完备的**生产级系统**。这也是整个开发周期最后的一块核心拼图。
