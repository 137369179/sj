# 验收摘要：账单结算与支付机制 (P3-2 核心探索)

## 1. 验证目标

- **摊位商业化**：打破 MVP 阶段中“免费入驻”的设定，让摊位具备真正的商业价值（标价）。
- **订单流水生成**：当主办方为摊主分配收费摊位后，系统能自动生成对应的待支付账单。
- **支付履约体验**：为摊主提供明确的账单页面，并完成（模拟的）在线支付闭环，最终更新报名状态。

## 2. 功能完整性

### 2.1 底层模型演进
- `Stall` 模型新增了 `price` 字段（Float）。
- 引入了全新的 `Order` 模型，记录 `applicationId`、`amount` 以及支付状态 (`pending`, `paid`) 等关键账单信息。
- `ApplicationStatus` 增加了 `paid` 状态节点，让整个业务状态机更加丰满。

### 2.2 主办方分发账单
- 当主办方调用 `assignStall` 时，系统会自动检查摊位价格。如果 `price > 0`，分配成功的同时会利用事务（Transaction）在底层悄无声息地生成一条绑定该摊主的 `pending` Order 账单。

### 2.3 摊主履约支付 (`/applications`)
- 摊主进入“我的报名”页，一旦其申请处于“已分配摊位”阶段，系统会在该卡片内弹出一个特别的**“账单与支付”区块**。
- 区块内明码标价，并提供“立即支付”按钮。
- **支付闭环 API**：摊主点击支付后，请求将被路由至 `/api/payments/[orderId]/pay`，该后端接口会安全地校验当前身份，并使用事务将订单标记为 `paid`，同时将报名的状态也更新为 `paid`，完成资金履约的完美流转。

## 3. 代码质量与环境说明

- 严谨的事务控制 (Prisma `$transaction`) 保障了 `Stall` 分配、`Order` 创建与 `Application` 状态更新的一致性。
- 对新增的支付流进行了完备的测试：拦截越权支付、校验账单状态。
- **当前测试库累计达 182 个测试用例，全站 100% 完美绿灯通过。**
